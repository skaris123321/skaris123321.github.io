## 2.1. Разработка дизайна

### 2.1.1. Описание структуры и внешнего вида проекта

Прежде чем приступать к вёрстке, нужно было понять, как сайт должен выглядеть и как по нему будут ходить пользователи. Поскольку основная аудитория — это инженеры и закупщики на предприятиях, которые открывают сайт в рабочее время с рабочего компьютера, перегружать интерфейс анимациями и декоративными элементами не имело смысла. Главное — чтобы человек быстро нашёл нужный товар и оформил заявку без лишних шагов.

Структура сайта выстроена по принципу воронки: сначала пользователь попадает на главную страницу, где видит, чем занимается компания. Затем переходит в каталог, выбирает категорию, находит конкретный товар и оформляет заказ. Каждый шаг логично вытекает из предыдущего, и нигде не возникает тупиков или непонятных переходов.

Шапка сайта одинакова на всех страницах — это принципиальное решение, которое даёт пользователю ощущение целостности. В ней расположены логотип компании, строка поиска по каталогу, кнопка перехода в каталог, иконка корзины со счётчиком добавленных товаров, номер телефона и ссылка на страницу ВКонтакте. На мобильных устройствах телефон и адрес электронной почты скрываются — на маленьком экране они только мешают, а позвонить можно и через подвал.

Подвал содержит контактные данные, логотипы партнёрских организаций и ссылку на политику конфиденциальности. Он тоже единый для всего сайта.

## 2.2. Разработка функционала

### 2.2.1. Структура сайта и карта страниц

Сайт состоит из восьми страниц. Главная находится в корне проекта, остальные — в отдельной папке для страниц каталога. Такое разделение даёт понятную структуру адресов и упрощает навигацию.

Пользователь начинает с главной страницы, где видит информацию о компании и может сразу перейти в каталог. Общий каталог — это своего рода «витрина» с четырьмя карточками категорий. Каждая категория ведёт на свою страницу с полным перечнем товаров и панелью фильтров: отдельные страницы предусмотрены для АВР, шкафов управления, установок компенсации реактивной мощности и ящиков управления электродвигателями. Страница конкретного товара универсальная — она получает параметры из адресной строки и отображает нужную карточку. Это удобно: не нужно создавать отдельный файл для каждой позиции, достаточно одного шаблона. Завершает путь пользователя страница корзины с формой оформления заказа.

Шапка и подвал подключаются на каждую страницу через специальную функцию динамической загрузки. Это значит, что если нужно изменить, например, номер телефона в шапке — достаточно поправить один файл, и изменение появится сразу везде.

> **📸 СКРИНШОТ 7.** Откройте страницу общего каталога. Сделайте скриншот страницы с четырьмя карточками категорий. Подпись: «Рисунок 7 — Страница общего каталога с категориями товаров».

**Программные модули сайта**

Клиентская часть разбита на несколько независимых модулей — каждый отвечает за свою область и не мешает остальным. Для каждой из четырёх категорий товаров написан отдельный модуль фильтрации: он загружает данные своей категории, строит панель фильтров и управляет отображением карточек. Такое разделение удобно тем, что при добавлении новой категории не нужно трогать уже работающий код — достаточно создать новый модуль по образцу существующих.

Управление корзиной вынесено в самостоятельный модуль, который работает на всех страницах одновременно. Именно он следит за тем, что добавлено в корзину, считает итоговую сумму и обновляет счётчик в шапке. Работа с данными товаров — загрузка, фильтрация, поиск — тоже выделена в отдельный модуль, чтобы не дублировать один и тот же код на каждой странице каталога. Поиск по всему ассортименту реализован как самостоятельный компонент: он перехватывает ввод пользователя в строке поиска и перенаправляет на страницу результатов. Всплывающие уведомления — например, подтверждение добавления товара в корзину — обрабатываются отдельным модулем, что позволяет вызывать их с любой страницы.

Серверная часть представлена одним скриптом на языке PHP. Он принимает данные оформленного заказа, проверяет их корректность, сохраняет в файл и возвращает клиенту подтверждение с номером заказа.

### 2.2.2. Реализация ключевых функций

**Каталог с фильтрацией**

Одна из главных задач при разработке каталога — сделать так, чтобы пользователь мог быстро найти нужный товар среди нескольких десятков позиций. Для этого реализована система фильтров. Данные каждой категории хранятся в отдельном файле в формате JSON. При открытии страницы категории скрипт загружает этот файл, анализирует все товары и автоматически строит панель фильтров — чекбоксы с уникальными значениями каждого параметра: бренд, номинальный ток, тип коммутации и другие. Если в каталоге есть только два бренда, то и в фильтре будет только два варианта — лишнего не показывается.

Когда пользователь отмечает нужные значения, список товаров мгновенно обновляется без перезагрузки страницы. Это важно для удобства: не нужно ждать, пока страница перезагрузится, — результат виден сразу [12].

**Система корзины**

Корзина — это, пожалуй, самый важный функциональный элемент сайта, потому что именно через неё проходит весь процесс покупки. Реализована она в виде программного класса, который хранит список добавленных товаров и умеет с ними работать: добавлять, удалять, менять количество, считать итоговую сумму.

Когда пользователь нажимает «В корзину», товар добавляется в список и сразу же сохраняется в памяти браузера. Благодаря этому корзина не пропадает, если закрыть вкладку или перезагрузить страницу — данные остаются до тех пор, пока пользователь сам их не удалит или не оформит заказ. Для каждой позиции генерируется уникальный идентификатор на основе её характеристик, поэтому если добавить один и тот же товар дважды — он не задвоится, а просто увеличится количество. Счётчик на иконке корзины в шапке обновляется в реальном времени через механизм событий — никакой перезагрузки страницы не требуется [13].

**Форма оформления заказа**

Форма оформления заказа решает одну нетривиальную задачу: у компании два типа клиентов — физические и юридические лица, и им нужны разные наборы полей. Физическому лицу достаточно указать имя, телефон и email. Юридическому лицу дополнительно нужно ввести название организации и ИНН — без этого менеджер не сможет выставить счёт.

Реализовано это через переключатель в верхней части формы. При смене типа клиента лишние поля плавно появляются или скрываются без перезагрузки страницы. Перед отправкой скрипт проверяет, что все обязательные поля заполнены и что телефон и email введены в правильном формате. Если что-то не так — пользователь видит подсказку рядом с проблемным полем. После успешной отправки корзина очищается и появляется сообщение с номером заказа.

### 2.2.3. Взаимодействие фронтенда с сервером

Клиентская и серверная части общаются по принципу REST API: браузер отправляет запрос, сервер отвечает в формате JSON. Это стандартный подход, который хорошо работает для подобных задач.

**Получение данных каталога.** Данные о товарах хранятся в файлах формата JSON и загружаются напрямую в браузере без обращения к серверному скрипту. Такой подход быстрее, чем запрос к базе данных, — браузер просто скачивает файл и разбирает его. Для каталога, который обновляется редко, это оптимальное решение.

**Отправка заказа.** Когда пользователь нажимает «Отправить заказ», браузер собирает все данные формы в один объект и отправляет его на сервер. Серверный скрипт проверяет, что данные пришли корректно, сохраняет заказ в файл и возвращает ответ с уникальным номером заказа. Этот номер показывается пользователю как подтверждение.

**Заглушка для интеграции с 1С.** В серверном скрипте есть закомментированный блок кода, который отвечает за передачу заказа в учётную систему 1С. Пока сайт работает как шаблон, этот блок не активен. Когда компания будет готова к полноценному внедрению, разработчику достаточно будет раскомментировать этот блок и указать адрес API 1С — и заказы начнут автоматически попадать в учётную систему без ручного переноса. Такое решение позволило передать компании рабочий сайт уже сейчас, не дожидаясь настройки интеграции.

## 2.3. Программная реализация

### 2.3.1. Кодирование веб-страниц

Разработка велась в редакторе VS Code, все изменения фиксировались через систему контроля версий Git. Страницы написаны вручную на HTML5 — без конструкторов и систем управления контентом. Это сознательный выбор: конструкторы добавляют лишний код, который замедляет загрузку, а для данного проекта скорость была одним из ключевых требований.

Все стили вынесены в один файл, что упрощает поддержку: если нужно изменить, например, цвет кнопок — правишь в одном месте, и изменение применяется везде. Скрипты разбиты на отдельные модули по функциональному назначению, чтобы не смешивать логику корзины, фильтров и поиска в одном файле.

Для реактивных элементов интерфейса — счётчика корзины в шапке и переключателя типа клиента в форме заказа — применена библиотека Alpine.js [14]. Она позволяет добавлять интерактивность прямо в HTML-разметке, без написания отдельного JavaScript-кода. Это удобно: видишь элемент в разметке и сразу понимаешь, как он работает, не нужно искать соответствующий скрипт в другом файле. Когда пользователь добавляет товар в корзину, модуль корзины генерирует событие об изменении, Alpine.js его перехватывает и автоматически обновляет число на иконке корзины в шапке.

### 2.3.2. Хранение данных

В проекте используется три способа хранения данных — каждый выбран под конкретную задачу.

**Хранение данных каталога.** Данные о товарах хранятся в файлах формата JSON — по одному файлу на каждую категорию. Это быстрее, чем база данных: браузер просто скачивает файл и разбирает его, никаких запросов к серверу и ожидания ответа. Для каталога, который обновляется редко, такой подход оптимален. Каждый товар описывается набором полей: артикул, бренд, тип коммутации, номинальный ток, количество вводов, цена, описание и путь к изображению.

**Хранение заказов.** Каждый оформленный заказ сохраняется в отдельный файл на сервере. Имя файла включает дату и время оформления, поэтому заказы легко найти и отсортировать. Менеджер компании может открыть папку с заказами и увидеть все поступившие заявки в виде обычных файлов — никакой специальной программы для этого не нужно. В будущем, когда будет настроена интеграция с 1С, эти файлы станут промежуточным звеном: сначала заказ сохраняется в файл, потом автоматически передаётся в учётную систему.

**Хранение корзины в браузере.** Данные корзины хранятся прямо в браузере пользователя. Это позволяет сохранять выбранные товары между сессиями — закрыл вкладку, открыл снова, а корзина на месте. Авторизация для этого не нужна [15].

## 2.4. Продвижение сайта

### 2.4.1. Разработка рекламной кампании

Сайт передан компании как готовый шаблон, поэтому полноценную рекламную кампанию запускать пока рано — сначала нужно наполнить каталог актуальными ценами и настроить хостинг. Но стратегию продвижения стоит продумать заранее, чтобы после запуска не тратить время на это с нуля.

Главная цель продвижения — чтобы потенциальные клиенты находили сайт сами, без холодных звонков. Конкретные ориентиры: рост органического трафика на 30% в первые полгода, не менее десяти заявок в месяц через форму заказа и снижение доли телефонных обращений с 90% до 60%. Это реалистичные цифры для небольшого B2B-сайта в промышленной нише.

Из каналов продвижения для данной аудитории лучше всего работают два: поисковая оптимизация и контекстная реклама в Яндексе [16]. Инженеры и закупщики ищут оборудование именно через Яндекс, а не через социальные сети. Соцсети полезны, но скорее для поддержания репутации, чем для прямых продаж.

### 2.4.2. SEO-оптимизация

SEO — это про то, чтобы сайт находили через поиск без платной рекламы. Для этого нужно понять, что именно вводят потенциальные клиенты в строку поиска, и убедиться, что на сайте есть страницы, которые отвечают на эти запросы.

Для подбора ключевых слов использовался Яндекс.Вордстат [17] — сервис, который показывает, сколько раз в месяц люди ищут тот или иной запрос. Запросы разделились на три группы. Высокочастотные — общие: «купить АВР», «шкаф автоматического ввода резерва», «производство НКУ». Среднечастотные — более конкретные: «АВР 100А купить», «шкаф управления насосом цена». Низкочастотные — очень точные: «АВР моноблочный 2 ввода 63А», «ящик управления электродвигателем Я5000». Последние особенно ценны: человек, который ищет конкретную модель с конкретными параметрами, уже знает, что ему нужно, и скорее всего готов купить.

На каждой странице сайта прописаны уникальные заголовок и описание — именно они показываются в результатах поиска. Заголовки страниц выстроены по иерархии: один главный заголовок на страницу, подзаголовки второго и третьего уровня для разделов. Это помогает поисковику понять структуру страницы.

Также подготовлены два служебных файла. Первый говорит поисковым роботам, какие страницы индексировать, а какие нет — служебные разделы сайта закрыты от индексации. Второй содержит карту всех страниц сайта с указанием, как часто они обновляются — это помогает поисковику быстрее находить новые страницы [18].

### 2.4.3. Контекстная реклама

Контекстная реклама — это платные объявления, которые показываются в поиске по нужным запросам. В отличие от SEO, результат виден сразу после запуска, но требует бюджета. Для данного проекта рекомендуется Яндекс.Директ — он охватывает основную часть целевой аудитории в России.

Пример того, как могло бы выглядеть объявление по запросу «купить АВР»:

```
Заголовок 1: Шкафы АВР от производителя — РОСЭК
Заголовок 2: Гарантия 18 месяцев. Доставка по России
Текст: Автоматический ввод резерва 25–800А. Документация в комплекте. Заказ онлайн.
```

Показывать такое объявление имеет смысл в рабочие дни с утра до вечера — именно тогда закупщики и инженеры ищут оборудование. По географии — Уральский федеральный округ и соседние регионы, где у компании есть клиенты.

### 2.4.4. SMM-продвижение

У компании РОСЭК уже есть страница ВКонтакте, ссылка на неё размещена прямо в шапке сайта. Это хорошая точка входа для тех, кто хочет посмотреть на реальные проекты компании перед тем, как сделать заказ.

Для развития этого направления стоит регулярно публиковать фотографии готовых изделий и смонтированных объектов — такие снимки уже есть в слайдере на главной странице сайта, их можно использовать и в соцсетях. Технические посты о том, как работает АВР или зачем нужна компенсация реактивной мощности, привлекают именно ту аудиторию, которая потом становится клиентами.

Таргетированная реклама ВКонтакте позволяет показывать объявления конкретным должностям — главным энергетикам, инженерам-электрикам, начальникам отделов закупок [19]. Это точнее, чем просто показывать рекламу всем подряд.

### 2.4.5. Аналитика

Без аналитики невозможно понять, работает продвижение или нет. Для этого рекомендуется подключить Яндекс.Метрику [20] — она бесплатная, хорошо работает с российской аудиторией и напрямую интегрируется с Яндекс.Директ.

Главное, что нужно настроить — это цели. Цель «Оформление заказа» срабатывает, когда пользователь успешно отправил форму. Цель «Добавление в корзину» — когда нажал кнопку «В корзину». Цель «Просмотр товара» — когда открыл карточку. Имея эти данные, можно увидеть, где именно люди уходят с сайта: зашли в каталог, но не добавили в корзину — значит, что-то не так с карточками товаров. Добавили в корзину, но не оформили — значит, проблема в форме заказа. Это позволяет улучшать сайт не наугад, а на основе реальных данных.

Если нажать на карточку, откроется страница товара (рисунок 4): несколько фотографий изделия, таблица с техническими характеристиками, цена и кнопка добавления в корзину. ### 2.5.4. Работа с корзиной и оформление заказа

Когда нажимаешь «В корзину», товар добавляется, а на иконке корзины в шапке появляется число — сколько позиций уже выбрано (рисунок 9). Можно продолжить выбирать товары или сразу перейти в корзину.

На странице корзины (рисунок 5) виден список всего, что добавлено. Для каждой позиции можно изменить количество кнопками «+» и «–» или удалить её совсем. Внизу — итоговая сумма.

Для оформления заказа нужно выбрать тип заказчика. Если выбрать «Юридическое лицо» (рисунок 10), появятся дополнительные поля — название организации и ИНН. Это нужно, чтобы менеджер мог выставить счёт. После заполнения всех полей нажимаешь «Отправить заказ» — данные уходят на сервер, корзина очищается, и на экране появляется сообщение с номером заказа (рисунок 14). Этот номер можно использовать при звонке в компанию, чтобы менеджер быстро нашёл заявку.

### 2.5.5. Работа менеджера с заказами

Серверная часть сайта предусматривает сохранение каждого оформленного заказа в отдельный файл на хостинге. Имя файла включает дату и время оформления, поэтому заказы легко найти и отсортировать. Менеджер компании открывает папку с заказами на сервере и видит все поступившие заявки — каждая в отдельном файле. Внутри — всё необходимое: тип клиента, контактные данные, список товаров с артикулами и количеством, итоговая сумма и комментарий, если клиент его оставил.

Поскольку сайт передан компании в виде шаблона и размещён на демонстрационном хостинге без поддержки PHP, функция сохранения заказов на сервере будет активирована при переносе на рабочий хостинг. В коде серверного скрипта эта логика уже реализована и готова к использованию. Когда будет настроена интеграция с 1С, заказы будут попадать в учётную систему автоматически, без ручного переноса.

### 2.5.6. Обновление каталога товаров

Добавить новый товар в каталог несложно: нужно открыть файл с данными нужной категории и добавить туда новую запись по образцу уже существующих. Сохранил файл — товар сразу появился на сайте. Никаких перезапусков, никакой компиляции. Это сделано специально, чтобы менеджер компании мог сам обновлять каталог без помощи разработчика.
